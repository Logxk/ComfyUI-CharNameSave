# ComfyUI-CharNameSave

按提示词中的角色名 tag 自动命名/分组保存图像的输出节点。

节点名：**Save Image by Char Tag（按角色名保存）**，位于 `image` 分类，用法与内置 Save Image 相同，但会从提示词里提取角色名来决定文件名或文件夹。

## 角色名的来源

1. **正向提示词输入口（推荐）**：节点有一个可选的「正向提示词」输入口，把**最终合成的提示词文本**（如 AnimaPromptPlus 的 `text` 输出）连进来。连接后只用该文本提取角色名。工作流里经过通配符/中间件/多场景切换时必须走这条路，否则静态扫描拿不到运行时真实文本。
2. **显式标记（最可靠）**：在提示词里写 `char:角色名`，兼容 `<char:角色名>` 写法：

   ```
   masterpiece, best quality, 1girl, solo, char:hakurei_reimu, red dress
   ```

3. **自动提取**（`自动提取角色名` 开启且未连接输入口、无 `char:` 标记时），按以下优先级：
   - 先剔除画师 tag（`@画师` 及 `@画师 (站名):权重`，Anima/danbooru 画师惯例），避免画师名被误认为角色
   - 再找 danbooru 惯例的 `角色名 (作品名)` 结构，如 `denia (wuthering waves)`、`professor niyaniya (blue archive)`
   - 最多取 `角色名数量上限` 个，多个名字用 `_` 连接
4. **兜底**：什么都没识别到时使用 `兜底名称`（默认 `ComfyUI`，即核心默认命名格式 `ComfyUI_00001_.png`）。提示词里只有裸 tag（无 `作品名` 括号结构）时不会乱猜，直接走兜底；这类提示词请用 `char:角色名` 标记。

未连接输入口时，工作流里所有文本节点的 widget 文本（正、负向）都会被静态扫描。

## 前端显示

节点每次运行后，节点下方会显示本次识别结果：

- `角色名: denia_(wuthering_waves)` —— 识别成功，此名称即文件名前缀
- `未识别到角色名，使用默认命名: ComfyUI` —— 走了兜底命名

## 两种模式

| 保存方式 | 效果 |
| --- | --- |
| `按角色命名文件`（默认） | 同一角色名共用一条编号序列：`output/hakurei_reimu_00001_.png`、`hakurei_reimu_00002_.png`… |
| `按角色分组文件夹` | 在输出目录下按角色名建文件夹，文件夹内编号：`output/hakurei_reimu/hakurei_reimu_00001_.png`… |

编号基于磁盘上已有的文件计算，删除文件后会从该编号继续；同一角色的多次生成自动连续编号。

## 参数（界面均显示为中文）

- `保存方式`（mode）：`按角色命名文件` / `按角色分组文件夹`（旧版本保存的英文值 `filename` / `folder` 仍被接受并自动映射，下拉框中保留仅为兼容旧工作流）
- `自动提取角色名`（auto_extract）：无 `char:` 标记时是否自动提取
- `角色名数量上限`（max_tags）：自动提取最多采用的角色名数量（默认 1；多角色建议用 `char:角色名` 显式标记）
- `编号位数`（padding）：默认 5，即 00001
- `兜底名称`（fallback_name）：提取失败时使用的名称

文件内嵌 prompt / workflow 元数据，可直接拖回 ComfyUI 复现工作流。图像文件名与文件夹名中的 `\ / : * ? " < > |` 等非法字符会被替换为 `_`。

## 安装

本目录已在 `ComfyUI/custom_nodes/ComfyUI-CharNameSave`，重启 ComfyUI 即可加载。无额外依赖。
